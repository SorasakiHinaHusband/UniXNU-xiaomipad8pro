# Tablet results, 2026-11-16 and the night to 11-17

All runs are RAM boots (`fastboot boot`) of macOS 27.3 with a volatile Data disk unless noted. "Confirmed" means a tablet log
line or recording shows it; "inferred" means an analysis concluded it and no run has shown it yet.

## Wi-Fi: macOS's own scan works (confirmed)

- Run wifi-iouc5 (commit `c048a0d7`, on main since the wifi3 merge): CoreWLAN's `scanForNetworksWithName` returns 5 networks
  in 21 ms, the cached scan list holds 16, the interface binds and stays bound, every record is served through our Apple80211
  user client (list end 5), 0 "Apple80211Scan Failed", no panic.
- The chain that got there, one link per run: the list end needs the user-client raw path (not the ioctl fallback); the
  user client must `prepare()` the caller's memory descriptor before it reads it; the full 32-bit ioctl command has to be
  accepted; a subset scan completes only after event 11 (scan cache updated) is posted.
- Next: the menu's network list, joining from the menu, and the country code (answered as a fixed firmware country for now;
  [drivers/wifi-menu.md](drivers/wifi-menu.md)).

## Hardware video decode (B10): firmware authenticated by the secure world (confirmed)

- V0b (commit `fc896e0f`, on main): the VideoToolbox frontend stub registers its service and guest property
  (`isRunningInGuest` true).
- V1b (branch): the video core powers up and down cleanly: PLL0 720 MHz, MVS0 240 MHz, the codec's power status on, all
  branches off again afterwards.
- V2 (branch, commit `e173dd2f`): the video firmware file (loaded at run time from the boot's addon, never in this repository)
  is parsed (22 program headers, 15 loadable segments), PAS 9 `init_image`, `mem_setup` and `auth_and_reset` succeed, the
  secure world reports the firmware authenticated, and PAS shutdown returns cleanly. One cycle so far; a three-cycle repeat
  is queued. No HFI traffic yet (V3).

## Sound (confirmed)

- macOS adopts our speaker as its default output device ("Built-in", 48 kHz); a test tone played by `afplay` is heard and
  recorded by the webcam microphone (run audio3, -25 dBFS).
- With amplifier gain 192 the same tone records at -14.2 dBFS (+10.8 dB, run audio-loud1). The recording shows two short gaps
  0.5 s apart; whether they are dropouts on the tablet is being analysed. Level and mute controls for the Sound settings
  slider are on the tablet now (run aud-controls1).

## Boot animation and boot windows (analysis closed, inferred root cause)

- At a real boot WindowServer finds no displayed surface of the mode's size on layer 0 when it configures the first
  display, defers the display configuration, and so shows no boot window. The chosen approach: the display driver offers
  the boot framebuffer as layer 0's displayed surface until the first swap. The first test image did not reach the new code
  path; the second (vid-bootsurf2) is being built.

## Lock-screen flicker (analysis in progress)

- Frames are lost upstream of the display driver; the 100 ms idle cadence is the system's own. The ESC transition is being
  measured as a GPU performance problem (per-job GPU timing, one switch toggled within a single boot).

## Test harness

- Specs are linted before they are queued (`spec-lint`), queue time-outs are raised to cover the run, and the runner refuses
  to boot when its ssh helpers are missing (two runs lost their ssh steps that way).
