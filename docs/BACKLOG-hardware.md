# Hardware backlog for the Xiaomi Pad 8 Pro (piano)

Status as of **2026-11-27**. The installed daily build is **v13.1y12q**. Three consecutive November 27 disk boots reached the login window
at +32 s with the owner's Data store verified. Earlier builds are named where they supplied the feature check.
[README](../README.md) · [Support status](STATUS.md) · [November 27 results](results-2026-11-27.md) · [November 26 results](results-2026-11-26.md)

The owner's 2026-11-11 rule is to use the Ubuntu port as the reference for piano-specific hardware. Generic desktop features
are outside this backlog. Section 4 records the OS switcher's write gate because it affects the boot partition. Driver pages
document the Ubuntu behaviour and the port's implementation.

Standing constraints for every item:

- Start with an opt-in boot argument and host checks, qualify on a RAM boot, then verify on a boot from disk before calling it installed.
- PianoPower alone controls startup, shutdown, restart and rail votes for the shared ADSP. Charging, audio and the SSC sensor hub rely on a healthy PianoPower level 2.
- Battery, sleep, interrupt, charging and thermal work keep priority.
- Keep per-unit calibration and addresses local. Access to `persist` is read-only.

**Done (installed)** means verified on a boot from disk. **Partial / nearly done** names the remaining check or fix.
**RAM only** means verified on a named test boot. **Host-only / Built, not run** means tablet qualification is pending.
**Open / Design only** and **Deferred** identify outstanding work. **Blocked on owner decision** applies to the specific gate in Section 4.

The Batch 6/7 27-kext live regression passed on RAM `v131y12u-ram2` (2026-11-27) with volatile Data,
the 60 Hz daily profile and zero crashes, GPU faults or panics. The installed daily build remains v13.1y12q.
