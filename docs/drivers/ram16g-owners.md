# RAM16G ownership proof before handoff

Analysis companion to [ram16g-plan2](ram16g-plan2.md). **CMA, lower DXE and FD currently contribute 0 proved MiB.** A successful EFI map describes firmware allocation types; it does not certify secure-world permissions, Gunyah memory-parcel ownership, or the last DMA reference. The m120c-120 map must be joined with those independent receipts before a slab is admitted.

This lane changes documentation only. No tablet access, image build, memory-map change, SCM call or push is authorized here. Future behavior must remain behind a default-off boot argument.

## Reference scope

Ubuntu v1.4.0 peels to commit `9f4b92899a7114c6af70a9ed64cd15a3f9b788f5`; its `kernel/source.json:3–9` pins Linux `83f0f89bed14a0cb7d582a26e72bced0387870f4`. References below use that Git object, not the newer working-tree HEAD of the read-only reference clones. Native base is `af341efd`; firmware pins are recorded in `unixnu.lock:23–48`.

D lines are reproducible derived text, not a checked-in DTS. A/D describe an earlier Android boot; they establish possible clients, not the native boot's current assignments.

The ownership paths were followed from reservation/phandle resolution through assignment, error handling and teardown: SCM/PAS, FastRPC secure maps and remote heap, remoteproc's image/DTB and additional regions, and Gunyah share/append/reclaim/CMA/protected shares. No reference checkout was changed. The comparison precedes any implementation; this task adds no driver implementation.

For all classes, retained firmware USB/UFS/display DMA may add an owner independent of the historical pool label. Native camera allocates frame/table backing from XNU (`package/PianoCamera/PianoCamera.cpp:821–855`); Iris admits XNU plus only the stage-1 modem run (`VideoHw.h:242–250`, `PianoVideo.cpp:715–735`); GPU ZAP stays at `0x9b09a000` (`PianoGpuInputs.h:21`). These bound those native submissions; they do not certify boot-firmware DMA or secure owners. ADSP ends exactly at `0xbd980000`, so the static DXE prefix `0xbd930000..0xbd980000` is a real conflict, excluded before rounding up to `0xbda00000`.

Arithmetic: CMA 128 slabs + lower DXE 186 + FD 8 = **322 audit slabs**. FD retains at least one, leaving ceilings of 256 + 372 + 14 = **642 MiB**, **0 proved**. Preserve the partial DXE edge pages, hwfence `0xd4e23000..0xd5100000`, the entire upper DXE remainder/Piano_Log, TZ, trust UI/OEM/VM shared reservations, Demura/ramoops and XBL ramdump. The ABL input `0xa8000000..0xb8000000` is a **separate** 256 MiB hypothesis (P `MemoryMapLib.c:28`), absent from the 322-slab audit; no release follows from this table.

## Fix-image gate

> **HOLD — 0 slabs admitted by this analysis.** For each proposed 2 MiB slab, require the successful final EFI descriptor coverage, affirmative HLOS ownership with no outstanding secure/VM borrow, and complete CPU/DMA lifetime evidence from the same native boot through ordinary resume. Missing observations are UNKNOWN and keep the slab excluded. A static DT reservation, disabled Linux driver, free CMA counter, successful CPU read, or absent SMMU fault cannot substitute for an ownership receipt. No state-changing SCM/RM operation is a read-only test.
