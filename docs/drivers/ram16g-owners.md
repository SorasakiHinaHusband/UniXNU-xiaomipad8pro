# RAM16G ownership proof before handoff

Analysis companion to [ram16g-plan2](ram16g-plan2.md). **CMA, lower DXE and FD currently contribute 0 proved MiB.** A successful EFI map describes firmware allocation types; it does not certify secure-world permissions, Gunyah memory-parcel ownership, or the last DMA reference. The m120c-120 map must be joined with those independent receipts before a slab is admitted.

This lane changes documentation only. No tablet access, image build, memory-map change, SCM call or push is authorized here. Future behavior must remain behind a default-off boot argument.

“Patch 0002” and “patch 0003” mean the repository's [extra-RAM patch](../../firmware/patches/darwinboot/0002-DarwinBoot-region1-extra-ram-reserve-and-publish.patch) and [EFI audit patch](../../firmware/patches/darwinboot/0003-DarwinBoot-audit-the-successful-EFI-map.patch); their citations count lines of the patch file. A bare `:line` fragment retains the named source/file immediately before it.

The ownership paths were followed from reservation/phandle resolution through assignment, error handling and teardown: SCM/PAS, FastRPC secure maps and remote heap, remoteproc's image/DTB and additional regions, and Gunyah share/append/reclaim/CMA/protected shares. No reference checkout was changed. The comparison precedes any implementation; this task adds no driver implementation.

## Reads the main session can collect now

These are instructions for the main session on m120c-120 once that audit boot is running, not tests performed in this lane. Run at idle and save another set during normal use and after the next ordinary resume; this runbook does not initiate suspend/resume, change boot arguments, bind/unbind a driver or reset a device. If early lines have rolled out of dmesg, use the existing retained USB capture's `log` replay. Keep the original capture, not just the filtered excerpt.

```sh
capture=$(mktemp -d)
date -u > "$capture/time.txt"
sysctl kern.bootsessionuuid kern.boottime kern.osversion kern.bootargs hw.memsize hw.pagesize > "$capture/boot.txt"
ioreg -p IODeviceTree -r -n chosen -d 1 -l -x -w0 > "$capture/chosen.txt"
ioreg -p IODeviceTree -r -n memory-map -d 1 -l -w0 > "$capture/memory-map.txt"
ioreg -p IODeviceTree -r -n efi -d 1 -l -w0 > "$capture/efi.txt"
ioreg -p IOService -l -w0 > "$capture/services.txt"
sudo dmesg > "$capture/dmesg.txt"
grep -F '"piano-efi-map-audit" = ' "$capture/chosen.txt" > "$capture/efi-map.ioreg"
python3 tooling/adt/read-efi-map-audit.py < "$capture/efi-map.ioreg" > "$capture/efi-map.txt"
grep -E '^EFI_MAP status=|^SUMMARY |^OWNER ' "$capture/efi-map.txt"
grep -Ei 'EFI_MAP_DMA|GEVNTADR|NativeUfs:.*(SID 0x60|DMA|smmu)|PianoDwc3:.*(takeover|SMR|S2CR|halt|reset)|PianoDpu:.*(pipe .*addr|SMMU)|PAS|mem_setup|arena|FastRPC|hwfence|VMID|Gunyah|QSEE|QTEE|assign' "$capture/dmesg.txt"
grep -Ei 'piano-sensors-arena|piano-boot-args|PianoPower|PianoSensors|PianoWifi|PianoDpu|PianoDwc3|NativeUfs|PianoCamera|PianoVideo' "$capture/services.txt"
```

When Python is host-only, decode the copied `efi-map.ioreg` there. On the existing USB-console owner session, `args`, `usb`, `log` are the read-only commands. If no session owns that console, the host can run `python3 tooling/native/usb-console.py --log-dir "$capture" --capture 25 --send args --send usb --send log` using a **host-local** mktemp capture directory. No reset/role command is part of this runbook. If `piano-dpu-snapshot=1` is already enabled, `sudo sysctl -n machdep.piano_dpu_snapshot` is an additional read (N `package/PianoDpu/DpuSnapshot.cpp:121–159`). It reports clock/timing/engine state and **does not enumerate all scanout PAs or SMMU mappings**; a missing sysctl is UNKNOWN, not a reason to change the boot in this lane.

R-EFI: apply [plan2's complete-map grading](ram16g-plan2.md#ram-efi-map-audit), retaining every descriptor and all 322 slabs, including a complete map with zero non-runtime slabs. Exclude every type 5/6 or `EFI_MEMORY_RUNTIME` intersection and every GOP overlap. CMA admission would additionally need full conventional/WB coverage. Lower DXE/FD boot-service descriptors require the later lifetime gate even when classified `non-runtime`; the decoder's `OWNER ... unknown` rows must remain unknown until separately proved. The runtime FD slab is a positive control. A blank, invalid, truncated or unsupported record gives no map proof.

On a reference tablet **already running Ubuntu** (not a request to boot one), the corresponding read-only inventory is:

```sh
uname -r
cat /proc/sys/kernel/random/boot_id /proc/cmdline
sudo dtc -q -I fs -O dts /sys/firmware/devicetree/base
sudo cat /proc/iomem
sudo dmesg | grep -Ei 'reserved mem|CMA:|fastrpc|remoteproc|gunyah|gh-|qsee|qtee|spss|assign|ath12k'
grep -E '^Cma(Total|Free):' /proc/meminfo
for rproc in /sys/class/remoteproc/remoteproc*; do
    test -d "$rproc" || continue
    printf '%s\n' "$rproc"
    cat "$rproc/name" "$rproc/state" "$rproc/firmware"
done
```

These reads locate that Linux boot's allocations/status only. For a dynamic reserved-memory heap, preserve both the effective DT and early reservation log/`/proc/iomem`; the original DTS `size` and `alloc-ranges` do not identify the allocated PA. `assigned reserved memory node` means a Linux device/pool attachment (`drivers/of/of_reserved_mem.c:734–743`), **not a successful SCM assignment**. Do not read a Gunyah CMA fd or `mmap` it to test freedom: the reference mmap path allocates pages (`drivers/virt/gunyah/vm_mgr_cma_mem.c:93–121`), and its read callback merely refuses shared parcels (`:124–148`), with no global ownership enumeration.

## Fix-image gate

> **HOLD — 0 slabs admitted by this analysis.**
>
> **Map:** R-EFI complete and same-boot; exclude runtime/GOP/unknown intersections, the fixed FD runtime slab and all fixed boundary exclusions. No blanket type-7/DXE/FD reclassification.
>
> **Owners:** R-SEC + R-VM affirm HLOS ownership of every page, no outstanding secure/VM borrow/SHM registration, and persistence through PAS startup, error paths and ordinary resume. Their current absence blocks the fix image even if m120c-120 reports conventional memory.
>
> **Lifetimes:** R-DMA + R-CPU + R-DUMP prove every last inherited CPU/device/deferred reference ends before the slab's first use, and native submissions/resume cannot silently reacquire it. Reads of current native buffers cannot substitute for the lost inherited state.
>
> **Admission:** Future implementation has an explicit, default-off per-class boot argument, exact independent slab allow-list, firmware/consumer agreement and effective-PA-override conflict checks. Unproved or failed rows stay excluded; absent/rejected records keep ordinary allocation available. This analysis changes no behavior or defaults and authorizes no image build.
>
> **Review record:** Attach the per-slab receipts and matching source/ABI evidence before changing maps or supplying a slab to macOS.
